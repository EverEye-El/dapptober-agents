## Official references and decisions

- [UMA OOv3 prediction-market guide](https://docs.uma.xyz/developers/optimistic-oracle-v3/prediction-market): explicit outcome assertions, separate bonds and callbacks. Their example covers outcome token creation but does not implement a trading venue. This build implements actual funded pari-mutuel stake purchases and stablecoin claims, with its limitations clearly exposed.
- [OOv3 interface source](https://github.com/UMAprotocol/protocol/blob/master/packages/core/contracts/optimistic-oracle-v3/interfaces/OptimisticOracleV3Interface.sol): exact `assertTruth`, `getMinimumBond`, settlement and callback signatures. No escalation manager replaces UMA. Only configured oracle can dispute/resolve callbacks; false assertions reopen the market for corrected evidence.
- [Approved identifiers](https://docs.uma.xyz/resources/approved-price-identifiers): `ASSERT_TRUTH` deprecated December 15, 2025; `ASSERT_TRUTH2` intended default since December 8, 2025. Constructor and adapter pin `ASSERT_TRUTH2` rather than copying stale quickstart defaults.
- [UMA network information](https://docs.uma.xyz/resources/network-addresses) and [Base Sepolia registry](https://github.com/UMAprotocol/protocol/blob/master/packages/core/networks/84532.json): Base and testnet deployments exist. Testnets lack production DVM support; mainnet integrations require monitoring. No address is invented or assumed verified from a static list. Environment configuration and live acceptance require checking exact oracle/currency/identifier compatibility.
- [UMA sandbox guide](https://docs.uma.xyz/developers/optimistic-oracle-v3/sandboxed-oracle-environment): local disputes are test doubles, not evidence of DVM consensus. The included mock tests contract callback boundaries, dispute lockout, false assertion reset and collateral conservation.
- [OpenZeppelin 5 utilities](https://docs.openzeppelin.com/contracts/5.x/api/utils): SafeERC20, ReentrancyGuard, Ownable, Math.mulDiv and human-readable Strings. No discretionary owner withdrawal or settlement override.
- [TypeSafe documentation](https://docs.typesafe.ai/introduction): reuse existing System One gate/routing adapter; Jev scores evidence and routes typed model forecasts, never sets final truth. Supplied evidence is bounded and logged; no fabricated live market/weather/sports observations.
- [Recharts ResponsiveContainer](https://recharts.github.io/en-US/api/ResponsiveContainer/): client-only responsive chart with sparse calibration bins and explicit counts. Pure score module is shared by API and UI.
- Bundled Next 16 route-handler documentation read before implementation. Standard Web Request/Response methods, node runtime and independently bundled shared source fit existing app boundaries.

## Chosen constraints

Small markets (100/contract, 256 traders/market), two-hour recommended live liveness, test clock only in demo, nontransferable stake accounting and no early selling. Pool odds are indicative and change with incoming stakes. No externally sourced autonomous forecast feed or multi-tenant custody is claimed. Registered wallets have onchain caps and permanent lane identity; one configured signer is executed by each agent API. Leaders are scores, not a Sybil-resistant identity system. New markets must define invalid-data refunds up front; unasserted stale markets refund after 30 days, pending oracle disputes stay locked until oracle resolution.
