## Official sources and decisions

- [World ID current integration guide](https://docs.world.org/world-id/idkit/integrate) and [official IDKit core](https://github.com/worldcoin/idkit/blob/main/js/packages/core/README.md): use current **4.x** SDK, server RP signing, `proofOfHuman({signal})`, production-only verification at `https://developer.world.org/api/v4/verify/{rp_id}`, require successful production response and persist canonical uniqueness. Older indexed `/api/v2/verify/{app_id}` guidance is insufficient for the current SDK. Legacy/device/selfie/document/session proof shapes are not admitted as this implementation's uniqueness credential.
- [ERC-8004 current specification](https://eips.ethereum.org/EIPS/eip-8004): use `ownerOf` plus `getAgentWallet`, authenticate the current authority and recheck it when querying. The reserved wallet clears on transfer. Registration proves provenance, not human status or honesty. Do not substitute Day 03's custom registry or resolve arbitrary user-supplied URLs.
- [SimpleWebAuthn server 14.x](https://simplewebauthn.dev/docs/packages/server) and [browser](https://simplewebauthn.dev/docs/packages/browser): use verified challenges/origin/RP/signatures/counters with required user verification and discoverable credentials. Node 22+ aligns with this repository. Passkeys provide returning authentication, not Sybil-resistant unique enrollment. P-256/RS256 are explicitly supported for browser interoperability; no attestation PII is stored.
- [Supabase direct and pooled Postgres connections](https://supabase.com/docs/guides/database/connecting-to-postgres) and [PostgreSQL row locking](https://www.postgresql.org/docs/current/explicit-locking.html): private server connection with atomic `SELECT ... FOR UPDATE` serializes uniqueness/claims across sessions and instances. Stable RP/action namespace prevents operator-secret rotation from resetting identities. A bounded aggregate model is appropriate for the small campaign; large-scale normalized storage, edge rate limits and retention policy remain release work.
- [OpenZeppelin cryptography](https://docs.openzeppelin.com/contracts/5.x/api/utils#EIP712), [SafeERC20](https://docs.openzeppelin.com/contracts/5.x/api/token/erc20#SafeERC20) and [viem typed-data verification](https://viem.sh/docs/actions/public/verifyTypedData): bind fixed funded rewards to EIP-712 campaign/person/recipient/chain/contract/deadline, require exact transfers and permanent claim uniqueness, and verify agent EOA/ERC-1271 signatures through the chain client.
- [TypeSafe System One](https://docs.typesafe.ai/): reuse the repository's fail-closed Jev adapter and routed small/large AI layer. Send verified risk facts, not raw proofs/passkey material/private human chats. AI scores never override hard lane/proof/contract checks.

All live provider calls remain unperformed without production app credentials and owner funding. Tests clearly label World/Jev/LLM/registry fixtures. Actual WebAuthn signature verification and Anvil deployment/USDC are separate evidence from a real World ID enrollment or public-chain production payout.
