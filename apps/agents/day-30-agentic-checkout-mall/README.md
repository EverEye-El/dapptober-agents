# AFTERHOURS — Day 30 / The Agentic Checkout Mall

A copper sunset mall for digital goods, with both merchant and shopping-agent workflows. Scout compares a machine-readable catalog under a daily gross-USDC budget and seller allowlist; each purchase requires explicit approval of the exact item/seller/price, then a separate payment. Included goods deliver actual original WAV, SVG and portable JSON files.

## Run

Use pnpm 10.2.0 / Node 22.12+. From root: `pnpm install --frozen-lockfile`, then `pnpm dev 30`; open `http://localhost:3030`. On a fresh checkout copy this app’s detailed `.env.example` into `.env.local`, preserving existing private values. This checkout already has different private operator/cookie secrets. Demo requires no provider, wallet, thirdweb or deployment credentials.

Browse stores or ask Scout for a synth loop, visual or agent kit. Set budget/approved sellers, inspect a comparison, check the explicit approval box, reserve its quote and pay with practice USDC. Download the actual deliverable. Open a dispute, resolve/refund and verify the balance returns while **gross spend does not reset**. A refund blocks future downloads but cannot erase a saved copy. Visitor merchant additions persist privately; authenticated operator additions publish to the public catalog.

## Architecture / onchain rules

`@dapptober/mall` implements catalog, rules, proposals, signed quotes, checkout, fulfillment, disputes/refunds and machine-readable `/api/catalog`. Shared experience/persistence packages supply private visitor sessions, authenticated shared operator space, exact saved wallet instructions and Supabase/local persistence. Supabase connections are separated by storage namespace to avoid nested catalog/workspace transactions exhausting the same connection pool. No other daily server is used.

`AfterhoursCheckout` takes the exact Circle USDC, merchant quote-signer address and independent arbiter. EIP-712 quotes bind order ID, product-version hash, buyer, seller, amount and expiry to this chain/contract. Only the buyer can pay; exact USDC is escrowed. Replays, self-trades, stale quotes and amounts over 1000 USDC are rejected. The buyer can accept to pay the seller; the seller can claim after 48 hours only if undisputed. The buyer can dispute before that deadline. Seller/arbiter can refund, and only the arbiter resolves a disputed payout. Every payout decrements reserved capital before transfer. No automatic deadline transaction or yield is claimed.

The agent never has a buyer private key or unbounded allowance. Hard budget/allowlist checks precede model calls and checkout. Refunds do not create new daily spending capacity. Quotes expire after five minutes. Updating rules invalidates the current proposal; price/version changes require a new comparison. The human owner can deliberately bypass offchain shopping rules by calling the contract directly; these rules constrain the application, not all unrelated wallet spending.

## Provider and payment setup

- **TypeSafe Jev / OpenAI:** real planning requires billed keys and explicit `MALL_PROVIDER_CONSENT=true`. Review sharing shopping preferences, budgets, allowed sellers and public catalog descriptions with TypeSafe (`https://api.typesafe.ai/v1/systemone`) and the configured OpenAI-compatible provider first. No shipping address/card information is collected. Jev gates budget/allowlist and routes small vs large reasoning; OpenAI generates structured comparisons/explanations, validated against eligible catalog IDs. Low confidence is highlighted; all purchases still require approval. Demo makes no provider calls.
- **thirdweb:** use the current unified v5 `ConnectButton`/`TransactionButton` payment flow, with a domain-restricted **public** `NEXT_PUBLIC_THIRDWEB_CLIENT_ID` set at build time. No thirdweb server secret is needed. Approval and escrow purchase are separate exact instructions. Cross-chain/swap auto-top-up is disabled (`payModal=false`) to preserve Base Sepolia/Base boundaries. This is the supported transaction payment path, not a legacy Pay SDK or an invented x402 scheme. The standard injected-wallet review is also available.
- **Wallet roles:** OWNER_ADDRESS is the buyer. MALL_MERCHANT_ADDRESS is an independent seller. MALL_QUOTE_SIGNING_PRIVATE_KEY is a separate server EOA used only to sign quotes; it needs no funds. MALL_ARBITER_ADDRESS is an independent dispute wallet used by deployment. Refund/resolve instructions name the required seller/arbiter signer; switch to that wallet before signing.

## Host an editable demo, then enable real funds

1. Configure a real **Supabase Session pooler PostgreSQL URI** as private `SUPABASE_DATABASE_URL`, unique stable operator/session secrets, workspace ID, `EXPERIENCE_STORAGE=supabase` and demo mode. Verify RLS/public-role denial, visitor isolation, operator catalog publishing and a genuine saved write/read. A local-disk alternative requires a mounted persistent `.data` volume and one app process; serverless must use Supabase.
2. Deploy this Vercel app directory or Docker `APP=day-30-agentic-checkout-mall`; build with `pnpm build 30`. Set exact final HTTPS `PUBLIC_ORIGIN`. Verify catalog additions, plan/approval/pay/download/dispute/refund, save/reload/redeploy and backup restore on the actual host. This demo release needs no public contract or paid models.
3. For actual funds, use **Base Sepolia 84532** first. Review the contract, 48-hour release/arbiter trust, digital-copy refund economics and operational limits. Configure independent buyer/seller/arbiter wallets, quote key/public address and chain-matched RPC; fund only small buyer USDC and role-wallet gas budgets.
4. Compile contracts (`pnpm test:contracts`), then `pnpm deploy:mall` prints unsigned deployment calldata using configured Circle USDC, derived quote-signer public address and independent arbiter. It does not broadcast. Deploy with a reviewed wallet/Foundry process, verify source and immutable constructor arguments, and set **MALL_CHECKOUT / MALL_CHECKOUT_CODE_HASH** from the reviewed deployed runtime.
5. Enable provider consent/keys and domain-restricted thirdweb public ID, then `pnpm readiness 30`. Set real mode only when dependencies are ready. Live access requires operator login. A live catalog has no seeded fallback merchant address: configure an actual independent seller first.
6. Rehearse genuine Base Sepolia approval → payment → exact receipt (two extra blocks) → file delivery → dispute → seller/arbiter payout/refund. Test expired/tampered/replayed quotes, wrong actor/chain/token/runtime, insufficient USDC, exhausted budget, provider outage, restart recovery and a repeated refund. File delivery refreshes chain state before allowing a live download.
7. Obtain independent security/economic review. Configure separate Base 8453 contracts, Circle USDC, Supabase, keys and final HTTPS production; repeat small-budget funded acceptance. Establish ingress/rate limits, quote-key rotation, arbiter availability, stuck-instruction monitoring, backup/restore and a retention/refund policy before public release.

Limits: digital templates are generated locally, not exclusive licensed physical goods. There is no shipping/inventory logistics service. No guaranteed refund after seller release; open a dispute within the contract window. A lost/unresponsive arbiter can leave disputed funds locked. Crypto cannot recall copied files. Public catalog merchant claims are curated assertions, not verified merchant reputation. The UI’s seller/arbiter controls simulate those roles in demo; real contracts enforce actual wallet authority. Product and order limits are 50/100; 100 paid decisions/day per workspace bounds provider costs. Infrastructure ingress controls are still required.
